# ASTAR Middleware + Simulator — Comprehensive Audit

**Date:** 2026-08-17
**Scope:** every PDF and Excel workbook in `docs/`, the `eap_middleware` + `gateway` + `simulator` + `config` + `tests` tree, against three goals:

1. **Full coverage compatibility with all machines** (SPTS fxP Omega, MueTec DaVinci 200 MC4/HC1, PTIQ SECS/GEM, NexGen MG21/MG22/MG22-300);
2. **Parallel connections from different machines at the same time** (up to 22 sessions, mixed HSMS active/passive) without cross-talk;
3. **No data loss per machine** (persist-before-ack, durable outboxes, per-lot CSV, per-machine separation, dedup).

Method: `pdftotext -layout` + `openpyxl` extraction of all 14 PDFs and the workbook, four parallel code audits (vendor-doc facts, profile coverage, parallel-session isolation, data-loss surface), independent re-verification of every headline finding, then fixes with regression tests. The four audit reports are preserved alongside this one:

- `docs/vendor/MACHINE_REQUIREMENTS_REPORT.md` — per-tool protocol facts from the source documents
- `docs/vendor/MACHINE_PROTOCOL_FACTS_SUPPLEMENT.md` — exact message tables, the SPTS alarm-CEID formula, spooling ECs, W-bit semantics, NexGen lot-start sequence
- `docs/COVERAGE_AUDIT_2026-08-17.md` — four-family profile/simulator coverage
- `tmp/parallel_sessions_audit.md` — 22-machine parallel-operation audit
- `docs/DATA_LOSS_AUDIT.md` — per-machine data-loss audit

Key protocol facts extracted (full detail in `docs/vendor/MACHINE_REQUIREMENTS_REPORT.md`):

- **NexGen MG**: no port/device-ID/HSMS role anywhere in the manual (E37 cited only) — the shipped defaults (5000/0/active) are documented guesses. Spooling explicitly **unsupported** (4 spool SVs 'not supported') → any middleware outage is unrecoverable data loss; `AlarmsSet` not supported → alarm-state unknown on reconnect. Events carry the originating load port in every PM report (stateless attribution).
- **SPTS fxP Omega**: connection parameters live in ECs (2nd host ECs 1000490–1000499: Connection_Type 0=Active/1=Passive, IP). Full spooling (S2F43/44, S6F23, non-volatile ECs). Alarm CEIDs computed from station/type/offset formula. Appendix E VID formula `station×10000 + type×100 + offset + 10000` with documented collisions (Etch vs Deposition share VID 32500).
- **DaVinci 200 MC4/HC1**: E30/E40/E87/E90/E94 profile; spooling exists but **defaults OFF** (EnableSpooling=0, MaxSpoolMessages=20). Events 3010001–3230002; all 282 marked 'Enabled: Yes' in the workbook. MC3 note: alarm list contains LP3 alarms although MC3 has no LP3.
- **PTIQ**: no vendor document; CEIDs/SVIDs arrive per installation in the EIB model export; the profile is deliberately generic.

### Deliberate, documented coverage limits (not defects)

- **DaVinci active subscription stays curated** (48 of 282): events without a canonical lifecycle meaning are recognised but not subscribed, so no misclassified rows enter per-lot CSVs. Full coverage = point the machine at `output/davinci200_mc4_hc1/EventSubscription.full.json` (banded).
- **NexGen constants are documentation-derived, never hardware-verified** (the manual disclaims its own constants); connection parameters are guesses.
- **SPTS Appendix E** has three families (DeltaAPM 134, VCE 17, PreHeat 13) with no documented offsets and ForceFill with no runtime value — the resolver refuses to guess (`ModuleLayoutError`) rather than mislabel.
- **PTIQ** CEIDs must come from the EIB export; config validation rejects an enabled real PTIQ machine without a complete subscription definition.
- **DaVinci SVID alias** `RecipeName → 1060007`: the workbook documents no PM2 SVIDs, so there is nothing to disambiguate.
- **Read-only runtime holds**: no S2F41/S2F17 anywhere; the only state-changing message is the opt-in S1F17 ON-LINE request (on by default only for NexGen).

### Simulator coverage

Every profile has a simulator preset (`profile` implementation via `ProfileSimulator`; `davinci_advanced` → `SecsGemEquipment`; `nexgen_advanced` → `NexGenMgSimulator`), including full-sweep replay modes for SPTS and MG. PTIQ simulated runs now emit only subscribed, mapped CEIDs (C4).

## 3. Parallel connections (22 machines simultaneously)

**Verdict: the isolation architecture is sound.** Each machine owns its `SecsMachineSession` → `GatewayHost` (own TCP connection/listener, own secsgem thread, generation-guarded callbacks). Journal/outbox/CSV/tracker/rate-limiter are shared sinks keyed by `endpoint_id`. Config rejects duplicate endpoint IDs, display names, overlapping passive binds (incl. 0.0.0.0 wildcard), and simulator listener conflicts. No cross-machine attribution vector was found.

Findings and fixes (details in `tmp/parallel_sessions_audit.md`):

| # | Finding | Severity | Fix |
|---|---|---|---|
| P1 | `PerLotCsvWriter` is a shared sink with **zero locking**, mutated by every machine's dispatcher thread plus the supervisor's replay pass; non-atomic `_seq_refs` refcounts can mark a journal entry done while rows are still buffered → silent CSV row loss; the replay pass can double-dispatch an entry the live path is mid-dispatch on → duplicate rows | **High** | Added a writer lock around all mutating operations and a service-level `_dispatch_lock` so live dispatch and replay re-read fresh journal state under the lock — exactly one thread applies an entry's sinks — **fixed** |
| P2 | The single global `ReconnectWatchdog` thread blocks up to T3=45 s on one machine's S1F3 liveness poll, stalling liveness checks and reconnect scheduling for all other machines (the documented OFF-LINE-DaVinci wedge) | Medium | Liveness checks now run on per-machine daemon threads; S1F3 round-trips are serialized per session so the liveness thread and SVID admin thread cannot interleave secsgem requests — **fixed** |
| P3 | `_write_status` check-then-index TOCTOU on `_simulators`/`_http_outboxes` can raise KeyError and silently kill the ConfigurationSupervisor daemon (auto-reload, command inbox, journal replay and mirror retries all stop) | Medium | `.get()`-based state read + try/except around the supervisor's status write — **fixed** |
| P4 | Restart command vs reconnect race can start a duplicate `GatewayHost` for one machine | Low | Restart commands and the reconnect identity-check+start are now atomic under `_reconcile_lock` — **fixed** |
| P5 | Unknown-CEID warning dedup set keyed (profile, ceid), so machine B never learns about a CEID drift machine A already saw | Low | Key now includes `endpoint_id` — **fixed** |
| P6 | `_recent_alarms` dedup dict grows without bound | Low | Entries older than 60 s pruned on insert — **fixed** |
| P7 | Stale subscription-provision worker can interleave S2F33/35/37 with a new generation's worker | Low | Worker captures its `host` and checks epoch+host identity before every round-trip — **fixed** |
| P8 | `machine_states()` iterates a live dict without a snapshot | Low | Snapshot with `list(...)` — **fixed** |

## 4. Data loss (per machine)

**Verdict: the ingestion chain is persist-before-ack throughout.** S6F11/S5F1 are acknowledged only after the message is durably journaled (WAL + `synchronous=FULL`); a storage failure returns ACKC6=1/ACKC5=1 so the tool retains the message. Retransmits collapse onto one delivery via the (endpoint, S/F, system bytes, body-digest) ingress key. Outboxes are durable SQLite with per-machine partitions; HTTPS outboxes are per-machine files keyed by a digest of the endpoint id. CSV files are written temp-file + fsync + atomic rename; the network mirror never blocks or invalidates local data.

Findings and fixes (details in `docs/DATA_LOSS_AUDIT.md`):

| # | Finding | Severity | Fix |
|---|---|---|---|
| D1 | A full outbox partition (100k pending) turned into **permanent telemetry loss**: after 10 replay attempts (~50 s) the journal entry was parked (`dispatch_status='dropped'`) with no requeue path | **High** | `OutboxFullError` is now treated as backpressure, never a defect: entries stay pending, replay keeps retrying, and the CSV sink still runs even when the outbox is full (publish-csv decoupled) — **fixed** |
| D2 | Pre-lot TTL pruning dropped rows **without journal accounting**: entries stayed `csv_status='pending'` forever, `holds()` kept replay skipping them, and the journal grew without bound | Medium | TTL-pruned rows now release their journal references (marked dropped with reason), like the cap path already did — **fixed** |
| D3 | Dead-letter machinery (`mark_dead`/`requeue_dead`) was unreachable; a permanently bad token pinged the endpoint forever and never purged | Medium | 4xx rows dead-letter after 5 consecutive permanent failures; new CLI `outbox-requeue --config [--endpoint-id]` makes the repair path reachable — **fixed** |
| D4 | Network-mirror crash window: a crash between the local write and the copy left the network copy permanently unmade with no record; mirror queue uncapped | Low | Mirror task is enqueued **before** the copy attempt and completed on success — **fixed** (uncapped queue left as documented operational limit) |
| D5 | Acked-but-unwritten CSV rows exist only in the journal (single disk = single point of failure); no directory fsync after rename | Medium (operational) | Directory fsync added after atomic renames on POSIX (no-op on Windows, where the file itself was fsynced); journal backup remains an operational recommendation — **partially fixed, see §6** |

## 5. Verification

- **Default suite:** 412 passed → now **421 passed, 5 skipped, 5 deselected** (4 live + 1 slow) after adding 9 regression tests — all green.
- **Slow suite:** the 22-machine mixed-profile, mixed-HSMS-role acceptance test passes (72 s).
- **New regression file** `tests/test_parallel_reliability_audit.py` (8 tests): CSV-writer parallel append integrity; live-dispatch vs replay exactly-once sink application (both directions); outbox-full never parks; TTL prune journal accounting; per-machine unknown-CEID warnings; superseded provision worker; DaVinci active subscription covers every alias.
- `compileall` clean for middleware, gateway, simulator, tests.

## 6. Remaining recommendations (no code defect)

1. **Real-hardware verification** for NexGen MG (243 constants + report ordering + connection parameters are documentation-derived) and PTIQ (installation CEIDs). This is the single highest-value next step; the hardware-regressions test is the designated home for corrections.
2. **Full-coverage commissioning:** to subscribe a DaVinci to all 282 events or an SPTS to all 225, point the machine at the banded `EventSubscription.full.json` files — a per-tool commissioning decision, now contained per family by the bands.
3. **Journal redundancy:** `ingress_journal.sqlite3` is the only copy of acked-but-not-yet-CSV'd events; back it up (or host on a second disk).
4. **SPTS Appendix E**: obtain the DeltaAPM/VCE/PreHeat offsets and the ForceFill runtime value from SPTS to complete the module-VID resolver.
5. **Mirror queue cap** for multi-day network-share outages (one row per lot file; bounded in practice by lot count, unbounded in time).
6. **MueTec workbook MC3 alarm anomaly** (LP3 alarms on a tool without LP3) — relevant when commissioning an MC3 variant.

## 7. Bottom line

- **Coverage:** 100% of documented CEIDs are recognised for all three documented vendors; NexGen is fully subscribed; DaVinci/SPTS active subscriptions cover everything the mapper classifies, with banded full coverage available per machine; simulator presets exist for all four families. Remaining gaps are commissioning/vendor-data questions, not code.
- **Parallelism:** 22 simultaneous isolated sessions verified; every real concurrency defect found (unlocked CSV sink, watchdog S1F3 stall, supervisor kill race, restart/reconnect race) has been fixed and regression-tested.
- **Data loss:** no ack-before-persist anywhere; the two real loss paths (outbox-full parking, TTL journal leak) are fixed; per-machine separation and dedup verified end-to-end.
